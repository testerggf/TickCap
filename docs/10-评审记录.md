iOS G3 完成功能闭环后，真实模拟器界面与 Web/06 原“果冻胶囊”方向存在明显视觉差距：极光退化为单色块、时间轴退化为等高白卡列表、快速记录位于页面顶部、Tab 使用临时图形，品牌识别与原生秩序均不足。

在不改变业务范围和 3 秒原则的前提下，提出“时间琥珀 Chrono Amber”作为果冻胶囊 G 的克制升级方向，并产出今日页高保真概念图。用户确认视觉方案，并明确要求：

1. 时间琥珀作为默认主题；
2. 果冻玻璃完整保留为独立可选主题；
3. 概念图中的文字体系和图标语言一并作为开发依据；
4. 先整理成正式设计文档，后续按文档开发。

### 裁决

**通过。** 06 已升级为双主题唯一视觉规范：

- `visualTheme=chronoAmber|jellyGlass` 与 `colorScheme=system|light|dark` 正交；
- 新用户默认 `chronoAmber`，已有明确偏好不得被覆盖；
- 两套主题共享页面、业务组件、数据、文案和交互，只通过 tokens 改变材质、色彩密度、圆角和动效；
- 默认页面结构采用“日期标题 + 时间列/轨道/节点/时长比例胶囊 + 底部滴答岛”；
- 系统图标按 06 §14 使用 SF Symbols 映射，Tab 固定为“今日 / 档案 / 报告 / 我的”；
- 今日页日期、摘要、时长、空隙、现在线、输入提示等文案按 06 §14 的动态模板实现；
- 概念图进入 `docs/assets` 作为气质和构图参考，但令牌、尺寸、状态和无障碍规则优先于图片细节。

### 计划影响

- 在 G3 与 G4 之间增加 G3-UI，先完成双主题视觉升级；
- G3 原出口只代表功能型 Alpha 通过，不代表双主题视觉验收完成；
- G3-UI 必须维持 30 次快速滴答 3 秒指标，并回归 8/50 颗时间轴性能；
- 四种主题/明暗组合先完成模拟器截图和对比度预验收，Dynamic Type、VoiceOver、Reduce Motion/Transparency 与 iOS 18.7.1 真机最终门禁仍在 G6；
- 本决策不新增第三方 UI 组件库，不扩大到 Widget、Live Activity、自定义主题色或第三套主题。

## 个人本地版优先决策（2026-08-10）

**用户已确认先将 TickCap 作为个人本地 App 使用，账号、服务端、云同步、远程推送和 TestFlight 多人内测后移。**

- SQLite 继续作为唯一业务事实来源，不引入 PostgreSQL，不安装 Docker/Homebrew 数据库；
- 现有 Markdown/JSON 导出只能证明数据可读，尚不能证明可安全恢复；本地版下一关键路径调整为“完整备份 → 导入恢复 → 本地提醒 → iPhone 14 长期自用”；
- 阅读导出与恢复备份必须分开：阅读导出仅包含当前有效内容，完整备份携带格式版本、SQLite schema 版本、设置与带软删除状态的实体；
- 完整备份不携带 `device_id/sync_cursor/outbox/event_outbox/sync_conflicts` 等设备或运行队列，避免恢复后制造重复同步和无意义诊断数据；
- 恢复默认按稳定 UUID 幂等合并，导入前自动保存现状，校验或写入失败必须事务回滚；覆盖恢复若未来增加，必须独立二次确认；
- 第一阶段采用系统分享保存到“文件”或 iCloud Drive，不依赖 App 沙盒内快照作为唯一保障；
- 现有本地规则复盘继续可用；真实模型 API key 不写入 App，云端 AI 随服务端能力后移；
- 云端原 G4A–F 保留为 v1.1 候选，不删除既有契约和 outbox 结构，避免未来迁移返工，但当前不实现半成品入口。

## iOS G4-L2 本地恢复出口（2026-08-10）

**通过。完整备份现已具备可验证、可预览、可回滚的恢复闭环。**

- 文件选择后按“JSON/格式 → Zod schema → SQLite schema 兼容 → canonical payload SHA-256 → 本机合并计划”顺序预检，失败时零写入；
- API 契约拒绝重复实体 UUID、重复封存日期、悬空标签 parent 和胶囊悬空 tag 引用；阅读导出 JSON 不能误当完整备份恢复；
- 合并规则收敛到 core：UUID 不存在则插入，备份 `updated_at` 严格更新才替换，相同或更早版本跳过；同一封存日期使用不同 UUID 时阻止整次导入；
- 用户确认前展示备份时间、实体总数、删除状态数和新增/更新/跳过数量，明确三类设置也会恢复；
- 确认后先在 App Documents 生成当前完整备份，再使用单个 SQLite exclusive transaction 恢复四张业务表与三类偏好；不导入 outbox/event outbox；
- Simulator 实库验证：37 条实体首次测试更新 1、跳过 36；再次导入更新 0、跳过 37；四表行数保持 14/19/1/3；
- 损坏 SHA-256 文件被预检拒绝且恢复点数量不变；临时 SQLite abort trigger 使事务中途失败后，本机测试标签与四表行数完整保持导入前状态；
- 失败提示不暴露 SQLite 内部错误；测试结束后临时触发器、临时数据库副本和损坏备份测试文件均已移除，正式备份与四份导入前恢复点 SHA-256 全部有效。
