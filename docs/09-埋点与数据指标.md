# 09 · 埋点与数据指标

> 没有测量就没有迭代。MVP 的生死判断（记录习惯是否成立）完全依赖这套数据，第一行业务代码和第一个埋点同时上线。

## 1. 原则

- 埋点走自有 `POST /events` 批量上报（Web 离线缓存；iOS 写入 SQLite event outbox，随同步冲队），不引入第三方统计 SDK（隐私承诺 + 体积）
- 事件命名 `对象_动作` 蛇形；属性只记业务必需，**永不记录 summary/detail 正文内容**
- 匿名可用：登录前用 `anon_id`（本地生成），登录后关联
- iOS `event_outbox.props_json` 仅允许 string/number/boolean/null；共享 core 层拒绝 `summary/detail/content/content_md/edited_md/note/text` 等正文属性名，不能只靠调用方自觉
- `record_done`、`capsule_edit/delete`、`gap_backfill`、`seal_done` 与对应业务实体/outbox 在同一 SQLite 事务写入；`app_open`、`record_start`、`seal_start`、`report_view`、`export_done` 可独立入队

## 2. 事件字典（MVP 全集）

| 事件 | 触发时机 | 关键属性 |
|------|----------|----------|
| `app_open` | 进入应用 | `entry`(direct/push/share/a2hs/notification_action), `platform`(web/ios), `is_pwa`, `app_version` |
| `record_start` | 打开滴答栏输入态 | `entry`(tickbar/gap/notification) |
| `record_done` | 胶囊创建成功 | `source`, `entry`(quick_tag/text/onboarding/gap/notification), `tag_count`, `has_summary`, `has_detail`, `has_mood`, `duration_min`, `elapsed_ms`(从 record_start 起) ★核心：elapsed_ms 中位数就是"3 秒原则"的体检报告 |
| `capsule_edit` / `capsule_delete` | 编辑/删除 | `field`(time/tag/summary/...) |
| `gap_backfill` | 从空隙补记 | `gap_minutes` |
| `seal_start` | 进入封存流程 | `capsule_count` |
| `seal_done` | 封存完成 | `capsule_count`, `streak`, `note_filled`(补一笔是否填写), `is_makeup`(是否宽限期补封) |
| `report_view` | 打开复盘/报告 | `type`, `scroll_pct`(读完程度) |
| `report_edit` | 编辑复盘 | `type` |
| `report_regenerate` | 重新生成 | `type`, `template_changed` |
| `report_fallback_shown` | AI 失败降级版展示 | `reason`(failed/timeout) |
| `reminder_sent` / `reminder_click` | 服务端发送 / 用户点击或 action | `channel`(web_push/apns/local), `snooze_level`, `action`(open/quick_tag/text_reply) |
| `notification_permission` | iOS/Web 通知权限请求完成 | `platform`, `result`(granted/denied/provisional), `trigger`(first_seal/settings) |
| `paywall_view` / `paywall_convert` | 付费引导展示/转化 | `trigger`(quota/weekly/backup/annual) （阶段二） |
| `a2hs_prompt` / `a2hs_done` | 添加主屏引导/完成 | |
| `onboarding_step` | 每屏完成 | `step`(1/2/3), `first_tag`(第2屏选了什么) |
| `export_done` | 阅读导出或完整备份完成 | `format`(markdown/json/backup) |
| `login_done` / `signup_done` | | `provider` |

iOS 同步失败、重试次数、checkpoint 等属于技术可观测性，写结构化诊断日志，不进入产品事件字典；日志同样禁止正文。

## 3. 指标定义（口径唯一，写死在看板 SQL 里）

| 指标 | 口径 |
|------|------|
| **北极星：周均封存天数** | 本周有 ≥1 次 `record_done` 的用户中，`seal_done` 去重天数的均值。健康线 ≥3.5（内测）→ 4.5（一年） |
| 活跃用户（DAU/WAU） | 当日/当周有 `record_done`（打开不算活跃，**记录才算**） |
| 日均胶囊数 | `record_done` 数 / 活跃日。健康线 ≥5（内测）→ ≥6 |
| 封存率 | `seal_done` 天数 / 有记录的天数。健康线 ≥50% |
| 次周留存 | 首次 `record_done` 后第 8–14 天再次 `record_done` 的比例。健康线 ≥35% |
| 3 秒达成率 | `record_done.elapsed_ms ≤ 3000` 的比例。健康线 ≥70%（tickbar 直点路径应 >90%） |
| 复盘阅读率 | `seal_done` 后 `report_view(scroll_pct≥80)` 的比例 |
| 复盘编辑率 | `report_edit` / 报告生成数（编辑 = 在意 = 付费前兆，也反映 AI 不够好，结合"补一笔"率交叉解读） |
| 提醒响应率 | `reminder_click` / `reminder_sent`。低于 15% 说明提醒策略在骚扰用户 |
| AI 成本比 | 当月 token 成本 / 当月收入 < 25%（[03](03-商业化设计.md) 红线） |

## 4. 看板（MVP 期一张页看全）

自建轻后台 `/admin/metrics`（或 Metabase 自托管连只读库）：
- 第一屏：北极星周趋势、DAU/WAU、封存率、次周留存 cohort 表
- 第二屏：3 秒达成率分布、记录来源占比（tickbar/gap/notification）、提醒响应率
- 第三屏：AI——生成量、失败率、降级展示率、编辑率、token 成本日报

内测期每周一拉一次数据做迭代决策会（就我们两个人，10 分钟）：**只看北极星和它的两个先导指标（3 秒达成率、封存率），其余是诊断用**。
