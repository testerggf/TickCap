# 04 · 路线图与落地计划

## 1. MVP 范围界定

**MVP 要回答的唯一问题：用户会不会形成"随手滴答 + 晚间封存"的日常习惯？**

因此 MVP 只包含习惯闭环的最短路径，其余一律砍掉：

### MVP 包含（P0）

1. 滴答记录：标签快捷输入 + 一句话概括 + 详情框 + 心情 + 时间自动推断 + 空隙补记
2. 竖向时间轴：胶囊卡片、时长视觉映射、编辑/删除/星标、日期切换
3. 封存仪式：回放动画（可先做简版）、streak 计数
4. AI 日复盘：默认模板 + KPT + 极简三行，共 3 个模板；可编辑、可补一笔
5. **提醒系统基础版**：可配置间隔与生效时段 + 智能节流（刚记录过则跳过、未响应自动降频）+ 晚间封存提醒
6. 档案馆：日历视图 + 点日期回看当日时间轴与复盘
7. 轻账号（邮箱验证码登录）+ 服务端存储 + Markdown/JSON 导出
8. Onboarding 三屏（30 秒内完成第一颗胶囊）+ PWA"添加到主屏幕"引导
9. 响应式：375 手机基准做到完美，桌面双栏布局做基础版

### MVP 明确不做

- 周报/月报/年报（复盘列表页放"敬请期待"占位，顺便收集点击埋点验证需求强度）
- 语音输入、小组件、正在进行模式
- 微信小程序与 App（架构已预留：`@tickcap/core` 共享包 + schema 同步字段，见 [05-技术架构](05-技术架构.md)）
- 微信登录/手机号登录（MVP 用邮箱验证码轻账号；Web-first 决定了数据必须存服务端，账号体系 MVP 必须有但做最轻的一种）
- 付费墙（MVP 期 AI 复盘每天免费 1 次，纯粹为控制成本；商业化在验证留存后开启）
- 那年今日、高光馆、洞察统计、AI 对话检索

### 平台选择（详见 [05-技术架构](05-技术架构.md)）

**Web H5 优先（自适应手机，最高优先级）→ 微信小程序（次优先级，补上提醒推送短板）→ iOS/Android App（预留）。**

Web 先行的优势：迭代最快（无审核、随时发版）、分享链路最短（周报/年报分享页点开即用，增长引擎天然顺畅）、一套代码覆盖手机与桌面。已知短板是提醒推送能力弱（iOS 需加到主屏才能收 Web Push），对策是产品内引导"添加到主屏幕"+ 晚间封存单点提醒保底，并以此作为小程序排第二优先级的理由（订阅消息补短板）。

技术栈：monorepo（业务逻辑 100% 共享于 `@tickcap/core`，三端 UI 各自原生手感）；Web 用 Next.js + Tailwind，小程序用 Taro（同为 React 心智），App 预留 Expo RN。数据结构从第一天就为多端同步做准备（每条记录带 UUID、更新时间戳、软删除标记）。

## 2. 迭代计划

### 阶段一 · MVP「能记录，能封存」（第 1–8 周）

- 第 1–2 周：monorepo 搭建、数据模型定稿、设计令牌落地、今日页代码原型（时间轴 + 滴答栏是设计重心，先在真机浏览器里把手感调对）；**同步启动域名 ICP 备案（流程 2–4 周，是关键路径）**
- 第 3–6 周：核心开发（记录流 → 时间轴 → 封存流 → AI 日复盘 → 档案馆 → 账号）
- 第 7 周：内测（20–50 人种子用户，从身边效率工具爱好者招募），埋点跑通
- 第 8 周：修问题，内测链接公开——Web 无审核，发个链接就能测，这是 Web 先行最大的红利

**阶段一验证指标**：内测用户次周留存 ≥ 35%；留存用户日均胶囊 ≥ 5；封存率 ≥ 50%。**不达标就调记录/封存体验，而不是加新功能。**

### 阶段二 ·「复盘有料，值得付费」（第 9–16 周）

- AI 周报 + 一键工作周报（画像 A 杀手锏）
- 模板系统完整版 + AI 人设
- **微信小程序上线（Taro，复用 core）+ 微信登录打通**——订阅消息补上 Web 提醒短板
- 会员体系上线（早鸟年费 + 限量终身）
- **快速回填**（90 秒批量补完漏记的一天）+ 日历导入草稿胶囊（Web 端接 CalDAV/ICS 订阅）
- 语音滴答
- 那年今日、洞察统计（近 30 天）

**验证指标**：试用→付费转化 ≥ 8%；周报打开率 ≥ 60%。

### 阶段三 ·「回忆与资产」（第 17–28 周）

- 月报、高光馆、全文搜索
- 自定义追踪目标
- 冷启动内容营销开跑（Web 链接 + 小程序码双入口，分享页转化链路打磨）
- **iOS/Android App 启动开发（Expo RN，复用 core/tokens/api）**——通知即记录（0 秒记录）、桌面小组件、离线优先同步在 App 端落地
- **年度报告必须在 11 月底前上线**——赶 12 月传播季，这是第一年最大的增长节点

### 阶段四 ·「第二大脑」（第二年）

- AI 对话式检索（和自己的人生数据对话）
- 基于长期数据的主动洞察（高效时段识别、情绪规律、目标偏航提醒）
- 端到端加密同步、自带 API Key
- 海外版

## 3. 里程碑指标看板

| 时点 | 北极星（周均封存天数/活跃用户） | 留存 | 商业化 |
|------|------|------|--------|
| MVP 内测结束 | ≥ 3.5 | 次周 ≥ 35% | — |
| 阶段二结束 | ≥ 4 | 次周 ≥ 40% | 转化 ≥ 8%，付费用户 300+ |
| 第一年结束 | ≥ 4.5 | 月留存 ≥ 25% | 付费用户 3,000+，AI 成本 < 收入 25% |

## 4. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| **记录习惯建立失败**（最大风险：再轻的记录也是行为改变） | 高 | 3 秒原则死守；空隙提示 + 晚间封存双钩子；onboarding 30 秒首记；MVP 阶段所有精力优先砸在这里 |
| AI 复盘"味同嚼蜡"，用户看一次就不看 | 高 | 结构化输入是根基；模板持续打磨（内部对同一天数据盲测多版 prompt）；"明日一问"制造与用户的私人连接；复盘编辑率是核心健康指标 |
| 提醒变骚扰 → 用户关通知/卸载（通知权限一旦关闭几乎不可逆） | 高 | 智能节流三重保险（刚记录跳过、刚打开跳过、未响应自动降频）；文案有人味；权限申请延后到首次封存后的高光时刻 |
| AI 成本失控 | 中 | 服务端代理统一计费；免费额度限次；日复盘用中档模型、长报告用高档模型；缓存与去重 |
| 隐私信任危机（记录类产品的生命线） | 中 | 本地优先架构、敏感胶囊不参与 AI、导出永久免费、隐私政策用人话写；绝不做广告变现 |
| 大厂/竞品抄袭 | 中 | 该品类的护城河是用户积累的数据资产与习惯，先发者的用户迁移成本高；把年度报告等情感体验做到别人抄不出灵魂 |
| 单人/小团队产能不足 | 中 | 严守 MVP 砍单；UI 采用成熟组件体系只重点打磨时间轴；AI 直接用成熟 API 不自建 |
| 国内上架合规（生成式 AI 备案、隐私合规） | 中 | AI 能力走已备案的大模型 API（如通义/豆包/DeepSeek 官方 API）；上架前完成个人信息保护合规自查；内测期用 TestFlight/蒲公英规避 |

## 5. 立即可做的下一步

1. **确认技术栈与目标平台**（建议：Expo RN 双端 / 或 iOS 先行）
2. 数据模型定稿（胶囊、标签、日封存、复盘的 schema，预留同步字段）
3. 时间轴 + 滴答栏的高保真原型（可先用代码直接做交互原型，验证 3 秒原则）
4. 日复盘 prompt 的第一版设计与盲测（拿自己真实的一天数据喂给 3 版 prompt 对比）
5. 用 TickCap 的理念记录 TickCap 的开发过程——第一天就开始 build in public
