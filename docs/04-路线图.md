# 04 · 路线图与落地计划

## 1. MVP 范围界定

**MVP 要回答的唯一问题：用户会不会形成"随手滴答 + 晚间封存"的日常习惯？**

因此 MVP 只包含习惯闭环的最短路径，其余一律砍掉：

### MVP 包含（P0）

1. 滴答记录：标签快捷输入 + 一句话概括 + 详情框 + 心情 + 时间自动推断 + 空隙补记
2. 竖向时间轴：胶囊卡片、时长视觉映射、编辑/删除/星标、日期切换
3. 封存仪式：回放动画（可先做简版）、streak 计数
4. AI 日复盘：默认模板 + KPT + 极简三行，共 3 个模板；可编辑、可补一笔
5. **提醒系统基础版**：可配置间隔与生效时段 + 智能节流（刚记录过则跳过、未响应自动降频）+ 晚间封存提醒
6. 档案馆：日历视图 + 点日期回看当日时间轴与复盘
7. 个人本地数据：SQLite 持久化 + Markdown/JSON 阅读导出 + 可恢复完整备份
8. Onboarding 三屏（30 秒内完成第一颗胶囊）+ Web PWA"添加到主屏幕"引导
9. Web 响应式：375 手机基准做到完美，桌面双栏布局做基础版
10. iOS 客户端：本地 SQLite 离线优先、完整备份/恢复、本地提醒与通知快捷记录（完整范围见 [11-iOS开发计划](11-iOS开发计划.md)）

### MVP 明确不做

- 周报/月报/年报（复盘列表页放"敬请期待"占位，顺便收集点击埋点验证需求强度）
- 语音输入、小组件、正在进行模式、灵动岛 Live Activity（iOS v1.1 再评估）
- 微信小程序与 Android App（保留 `@tickcap/core`/`tokens`/`api` 复用路径，不在 iOS v1 同期开发）
- 微信登录/手机号登录（连同邮箱轻账号统一后移到 v1.1 评审）
- 个人本地版 v1 不做邮箱账号、服务端存储、云同步、远程推送和在线 AI；这些能力保留为 v1.1 候选，不阻塞自用闭环
- 付费墙（MVP 期 AI 复盘每天免费 1 次，纯粹为控制成本；商业化在验证留存后开启）
- 那年今日、高光馆、洞察统计、AI 对话检索

### 平台选择（详见 [05-技术架构](05-技术架构.md)）

**保留已交付的 Web H5 M1 → iOS-first（当前最高优先级）→ 微信小程序 / Android 后续复用。**

Web M1 继续承担快速验证与桌面访问；iOS 当前优先解决可靠本地数据、可恢复备份、原生提醒和通知快捷记录。2026-08-10 起先交付个人本地版，云端能力后移；两端仍共用领域规则、设计令牌与数据契约，不复制产品逻辑。

技术栈：monorepo（业务逻辑 100% 共享于 `@tickcap/core`，各端 UI 保持原生手感）；Web 用 Next.js + Tailwind，iOS 用 Expo React Native + 必要 Swift 扩展，小程序后续用 Taro。数据结构统一采用 UUID、更新时间戳、软删除和增量同步游标。

## 2. 迭代计划

### 阶段一 A · Web M1「能记录，能封存」（已交付）

- monorepo、tokens、core、Web 本地主链路和自动化基线已经交付；
- Web M1 保持可运行与回归，不在 iOS 开发中破坏本地数据；
- iOS 个人本地版优先；账号、云同步、AI SSE 与远程推送移至 v1.1 候选。

### 阶段一 B · iOS-first MVP（预计 8–12 周）

- G0：路线图、架构、API/同步契约与验收标准对齐；
- G1：Expo/iOS 18.7.1 真机风险样机，验证 SQLite、通知、深链和签名；
- G2：共享 `core/tokens/api` 收敛；
- G3：iOS 本地模式完整主链路；
- G4-L：完整备份、校验、导入恢复与备份提醒；
- G5-L：本地提醒与通知快捷记录；
- G6-P：iPhone 14 / iOS 18.7.1 真机安装与个人长期使用验证。

邮箱账号、服务端、云同步、远程推送、在线 AI 和多人 TestFlight 作为 v1.1 候选，待个人本地版稳定后另行审核。

**阶段一验证指标**：内测用户次周留存 ≥ 35%；留存用户日均胶囊 ≥ 5；封存率 ≥ 50%；3 秒达成率 ≥ 70%。**不达标就调记录/封存体验，而不是加新功能。**

### 阶段二 ·「iOS 系统入口 + 复盘有料」（iOS v1 稳定后）

- AI 周报 + 一键工作周报（画像 A 杀手锏）
- 模板系统完整版 + AI 人设
- iOS v1.1：Widget、App Shortcuts、Action Button；Live Activity 仅在“正在进行模式”获批后开发
- 会员体系上线（早鸟年费 + 限量终身）
- **快速回填**（90 秒批量补完漏记的一天）+ 日历导入草稿胶囊
- 语音滴答
- 那年今日、洞察统计（近 30 天）

**验证指标**：试用→付费转化 ≥ 8%；周报打开率 ≥ 60%。

### 阶段三 ·「多端扩展与回忆资产」

- 月报、高光馆、全文搜索
- 自定义追踪目标
- 微信小程序（Taro）+ 微信登录；以真实渠道需求决定排期
- Android App 复用 Expo RN/core/tokens/api；先完成 Android 专项适配与验收，禁止把 iOS 二等移植
- 冷启动内容营销开跑（Web 链接、App Universal Link、小程序码按已上线端组合）
- **年度报告必须在 11 月底前上线**——赶 12 月传播季，这是第一年最大的增长节点

### 阶段四 ·「第二大脑」（第二年）

- AI 对话式检索（和自己的人生数据对话）
- 基于长期数据的主动洞察（高效时段识别、情绪规律、目标偏航提醒）
- 端到端加密同步、自带 API Key
- 海外版

## 4. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| **记录习惯建立失败**（最大风险：再轻的记录也是行为改变） | 高 | 3 秒原则死守；空隙提示 + 晚间封存双钩子；onboarding 30 秒首记；MVP 阶段所有精力优先砸在这里 |
| AI 复盘"味同嚼蜡"，用户看一次就不看 | 高 | 结构化输入是根基；模板持续打磨（内部对同一天数据盲测多版 prompt）；"明日一问"制造与用户的私人连接；复盘编辑率是核心健康指标 |
| 提醒变骚扰 → 用户关通知/卸载（通知权限一旦关闭几乎不可逆） | 高 | 智能节流三重保险（刚记录跳过、刚打开跳过、未响应自动降频）；文案有人味；权限申请延后到首次封存后的高光时刻 |
| AI 成本失控 | 中 | 服务端代理统一计费；免费额度限次；日复盘用中档模型、长报告用高档模型；缓存与去重 |
| 隐私信任危机（记录类产品的生命线） | 中 | 本地优先架构、敏感胶囊不参与 AI、导出永久免费、隐私政策用人话写；绝不做广告变现 |
| 大厂/竞品抄袭 | 中 | 该品类的护城河是用户积累的数据资产与习惯，先发者的用户迁移成本高；把年度报告等情感体验做到别人抄不出灵魂 |
| 单人/小团队产能不足 | 中 | 严守 MVP 砍单；UI 采用成熟组件体系只重点打磨时间轴；AI 直接用成熟 API 不自建 |
| 国内上架合规（生成式 AI 备案、隐私合规） | 中 | AI 能力走已备案的大模型 API（如通义/豆包/DeepSeek 官方 API）；上架前完成个人信息保护合规自查；内测期用 TestFlight/蒲公英规避 |

2. 完成 G4-L2 导入预览、导入前自动备份、UUID 幂等恢复与事务回滚

4. 个人本地版稳定后再评审账号、云同步、在线 AI 与 TestFlight 多人内测
