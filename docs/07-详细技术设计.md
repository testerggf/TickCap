# 07 · 详细技术设计（开发实施规格）

> 本文是 [05-技术架构](05-技术架构.md) 的下钻实施规格：领域规则的精确定义、数据库 DDL、API 契约、前后端模块设计、测试与验收标准。**开发以本文为准；与 05 概览有出入处，以本文为准。**

## 1. 术语表（全项目统一用语）

| 术语 | 英文/代码名 | 定义 |
|------|------------|------|
| 胶囊 | Capsule | 一条时刻记录（时间段 + 标签 + 内容） |
| 滴答 | Tick | 完成一次记录的动作 |
| 时间轴 | Timeline | 一天的胶囊竖向排列视图 |
| 封存 | Seal | 对一天执行"确认 + 生成复盘 + 归档"的闭环动作 |
| 归属日 | date | 胶囊/封存所属的"逻辑日"（由日界决定，见 §2.1） |
| 日界 | day boundary | 逻辑日的分界时刻，默认凌晨 04:00 |
| 默认起床时间 | wake default | 当天第一颗胶囊的默认开始时刻，默认 07:00 |
| 空隙 | Gap | 相邻胶囊之间 ≥15 分钟的未记录区段 |
| 连续封存 | Streak | 连续封存的天数 |
| 草稿胶囊 | Draft capsule | 由日历/健康数据自动生成、待用户确认的胶囊 |

## 2. 领域规则规格（核心业务逻辑的唯一权威定义）

> 这些规则全部实现在 `@tickcap/core`，三端共享，必须 100% 单元测试覆盖。

### 2.1 归属日（date attribution）

- 用户设置**日界**（`day_boundary`，默认 04:00）。胶囊 `start_at` 换算到用户时区后，若时刻 < 日界，归属日 = 前一天；否则为当天。
- 例：日界 04:00，凌晨 01:30 记录的「夜宵」归属昨天的时间轴——符合人类心智（"昨晚"）。
- **修改日界不重算历史数据**，只影响之后的记录（避免历史时间轴突变）。
- 跨日界的胶囊（如睡眠 23:00–07:00）：归属日按 `start_at` 判定，允许 `end_at` 越过日界；当日时间轴尾部显示"→ 次日 07:00"截断样式。单颗胶囊时长上限 24h。

### 2.2 时间自动推断（infer times）

新胶囊默认时间段：

```
end_at   = now
start_at = 有同归属日的上一颗胶囊 ? 上一颗.end_at
         : max(now - 1h, 今日归属日的默认起床时间)
约束     = start_at 向下取整到分钟；若 start_at ≥ end_at 则 start_at = end_at - 1min
```

- 时长下限 1 分钟；手动调整步进默认 15 分钟（可设 5 分钟）。
- **重叠策略：允许重叠**（现实中"边吃饭边开会"存在，禁止重叠会造成编辑连锁反应）。服务端只校验 `end_at > start_at`；时间轴对重叠胶囊做横向缩进并列渲染。

### 2.3 空隙（gap）

按 `start_at` 排序的相邻胶囊之间，`next.start_at - prev.end_at ≥ 15min` 即渲染空隙区段（虚线，可长按补记）。最后一颗胶囊到"现在"之间同理。空隙是纯前端派生数据，不落库。

### 2.4 封存与 Streak

- 封存 = 对某归属日创建 `day_seal` 记录（触发 AI 日复盘生成）。已封存的日子可**解封**编辑，再次封存更新 `sealed_at`，streak 不受影响（以首封时刻为准）。
- **宽限规则**：D 日可在 D+1 的 12:00（用户时区）前封存并保持连续——晚上忘了、第二天早上补封不断签。
- Streak 计算：`streak(D) = 前一日在宽限内完成过封存 ? streak(D-1) + 1 : 1`，在封存时计算并快照到 `day_seals.streak`（避免历史回算）。
- 空轴不可封存（至少 1 颗胶囊），按钮置灰并提示。

### 2.5 敏感胶囊（is_private）

标记后：参与本地展示与统计**时长**，但其 `summary/detail` 在 AI 请求打包层被硬性剔除（见 [08 §2](08-AI复盘技术设计.md)）；导出时正常包含（数据是用户自己的）。

## 3. 数据库设计（PostgreSQL DDL 核心）

所有表统一四件套：`id uuid pk default gen_random_uuid()`、`created_at`、`updated_at`、`deleted_at`（软删除，查询默认过滤）。仅列业务字段：

```sql
users             (nickname, email unique, timezone text default 'Asia/Shanghai',
                   day_boundary_min int default 240,      -- 04:00
                   wake_default_min int default 420,      -- 07:00
                   time_step_min int default 15,
                   is_pro bool default false, pro_expires_at timestamptz)

auth_identities   (user_id fk, provider text check in ('email','wechat','phone'),
                   identifier text, unique(provider, identifier))

verification_codes(email, code_hash, expires_at, attempts int default 0)

refresh_tokens    (user_id fk, token_hash, expires_at, revoked_at)

tags              (user_id fk null,          -- null = 系统预置
                   name, emoji, color, parent_id fk null, sort int,
                   archived_at timestamptz)

capsules          (user_id fk, date date not null,        -- 归属日，冗余存储
                   start_at timestamptz, end_at timestamptz,
                   tag_ids uuid[] default '{}',            -- 主标签 = tag_ids[0]
                   summary text, detail text,
                   mood smallint check (mood between 1 and 5),
                   is_highlight bool default false, is_private bool default false,
                   status text default 'confirmed' check in ('draft','confirmed'),
                   source text check in ('manual','notification','backfill',
                                         'calendar_draft','onboarding'),
                   check (end_at > start_at),
                   check (end_at - start_at <= interval '24 hours'))
                   -- index: (user_id, date), gin(tag_ids)

day_seals         (user_id fk, date date, unique(user_id, date),
                   sealed_at timestamptz, first_sealed_at timestamptz,
                   note text,                              -- 手写"今日一句话"
                   streak int)                             -- 封存时快照

ai_reports        (user_id fk, type check in ('daily','weekly','monthly','yearly'),
                   period_start date, period_end date,
                   template_id fk, persona text,
                   content_md text, edited_md text,        -- AI 原文 与 用户编辑版分开存
                   model text, prompt_version text,
                   input_tokens int, output_tokens int,
                   status check in ('pending','streaming','done','failed'))
                   -- 同周期可多行（重新生成留历史），取 created_at 最新且 done 的为当前版

templates         (user_id fk null, kind, name, spec jsonb)  -- 结构 + 口吻参数

reminder_settings (user_id pk, interval_min int default 60,
                   active_from_min int default 480, active_to_min int default 1320,
                   weekday_mask int default 127, paused_until timestamptz,
                   seal_remind_min int default 1290,       -- 21:30
                   snooze_level int default 0)             -- 自动降频档位

push_subscriptions(user_id fk, endpoint text unique, keys jsonb, ua text)

events            (id bigserial, user_id null, anon_id, name, props jsonb, ts)
```

关键决策：
- `capsules.date` 冗余存归属日，所有按天查询走 `(user_id, date)` 索引——把时区/跨天判断锁死在写入时刻的 `core` 逻辑里，读取永不再算。
- `tag_ids` 用 `uuid[]` 而非关联表：标签数量少、永远整组读取、无需按标签 join 查胶囊以外的场景（按标签统计走 GIN 索引），省一张表和 N 次 join。
- AI 报告"原文/编辑版"分列，重新生成插新行——用户编辑永不被覆盖（产品红线）。

## 4. API 契约

通用约定：`Authorization: Bearer <JWT>`；请求体/响应体均为 JSON；时间一律 ISO 8601 UTC；分页用 `?cursor=&limit=`。

### 4.1 错误码

| HTTP | code | 含义 |
|------|------|------|
| 400 | `VALIDATION_FAILED` | 参数校验失败（附 `fields` 明细） |
| 401 | `TOKEN_EXPIRED` / `TOKEN_INVALID` | 前端触发静默刷新或登出 |
| 403 | `QUOTA_EXCEEDED` | AI 次数用尽（附 `quota` 信息，前端展示付费引导文案） |
| 404 | `NOT_FOUND` | |
| 409 | `ALREADY_EXISTS` | 幂等冲突（如重复封存），响应附既有资源 |
| 429 | `RATE_LIMITED` | 附 `retry_after` |
| 500 | `INTERNAL` | 前端统一"稍后再试"，写操作进离线重试队列 |

### 4.2 端点清单

```
# 认证
POST /auth/email/code        {email} → 204        限流：同邮箱 1次/分钟、5次/天
POST /auth/email/verify      {email, code} → {access_token, refresh_token, user}
                              码 6 位数字，10 分钟有效，错 5 次作废；哈希存储
POST /auth/refresh           {refresh_token} → 新 token 对（旋转式，旧 token 作废）
POST /auth/logout            → 204
DELETE /auth/account         → 204   注销：软删用户 + 7 天冷静期后物理清除（合规必须）

# 胶囊
GET    /capsules?date=2026-07-27           → {capsules: [...]}
POST   /capsules             客户端生成 id（UUID v7），服务端按 id 幂等（断网重试不重复）
                              {id, start_at, end_at, tag_ids, summary?, detail?,
                               mood?, source} → 201 {capsule}   （date 由服务端 core 计算）
PATCH  /capsules/:id         局部更新；改 start_at 会重算 date
DELETE /capsules/:id         软删除 → 204
POST   /capsules/batch       [{...}, ...] → 快速回填用，≤50 条/次（P1）

# 标签
GET /tags · POST /tags · PATCH /tags/:id（archived_at 归档，不物理删）

# 封存与报告
POST /days/:date/seal        {note?} → 201 {seal, report_id}    重复封存 → 409 + 既有 seal
DELETE /days/:date/seal      解封 → 204（streak 不变）
GET  /days?month=2026-07     月历数据：[{date, sealed, top_tag_color, capsule_count}]
GET  /reports?type=daily&cursor=
GET  /reports/:id
GET  /reports/:id/stream     SSE：event: delta {text} / done / failed
POST /reports/:id/edit       {edited_md}
POST /days/:date/report      重新生成（可换 template_id/persona）；限流 5 次/天/用户

# 其他
GET/PUT /reminder-settings
POST /push/subscribe         {endpoint, keys} · DELETE /push/subscribe
GET  /export                 → 202 {job_id}；GET /export/:job_id → 打包下载 URL（zip: md+json）
GET  /stats?from=&to=        标签时长聚合、日均胶囊数（洞察页数据源）
POST /events                 埋点批量上报 [{name, props, ts}]，≤50 条/次
GET  /me · PATCH /me         （timezone/day_boundary/wake_default 等设置）
```

## 5. 前端技术设计（apps/web）

### 5.1 目录与路由

```
apps/web/src/
├── app/
│   ├── (marketing)/           # 官网落地页、分享页（SSR/SEO）
│   │   └── s/[shareId]/       # 报告分享页（含 OG image 生成）
│   └── (app)/                 # 应用本体（登录态，CSR 为主）
│       ├── today/             # 今日页（默认路由）
│       ├── archive/           # 档案馆（+ /archive/[date] 当日详情）
│       ├── reports/           # 报告（+ /reports/[id]）
│       ├── settings/
│       └── onboarding/
├── components/                # timeline/ capsule/ tickbar/ calendar/ report/ ui/
├── stores/                    # zustand：session / today / ui
├── lib/                       # queryClient、offline-queue、push、analytics
└── styles/                    # tokens 生成的 CSS 变量 + tailwind 配置
```

### 5.2 数据流与离线队列

- 服务端状态全部走 **TanStack Query**（key 约定：`['capsules', date]`、`['days', month]`、`['report', id]`）。
- **写操作乐观更新**：滴答 → 本地立即上轴（UUID v7 前端生成）→ 后台 POST；失败入 **离线队列**（IndexedDB，`idb` 库）：指数退避重试，恢复网络自动冲队；因 id 幂等，重试永不产生重复数据。队列中的胶囊在 UI 上带一个极小的"待同步"点，不打扰。
- 今日页数据 PWA 缓存最近快照，离线可看可记（记录进队列）。

### 5.3 关键组件规格

| 组件 | 要点 |
|------|------|
| `<Timeline>` | 虚拟化按需渲染（一天 ≤50 颗通常无需虚拟化，历史页月视图需要）；重叠胶囊横向缩进并列；空隙派生渲染；"现在线"每 30s 重算位置 |
| `<CapsuleCard>` | 果冻玻璃材质（tokens 驱动）；高度 = clamp(44, 时长映射, 120)；视口外停用 backdrop-filter（IntersectionObserver 切换 class） |
| `<TickBar>` | 玻璃岛；标签按使用频率排序（本地统计）；展开态为半屏弹层（Radix Dialog + 自定义样式） |
| `<SealFlow>` | 三幕流程组件；复盘 SSE 渐进渲染（`EventSource`）；封存动画 Motion 编排 |
| `<MonthCalendar>` | 档案馆月历；数据源 `GET /days` |

### 5.4 PWA 与提醒

- Serwist 生成 SW：应用壳 + 今日数据缓存；`beforeinstallprompt` 捕获后在首次封存完成时机弹"添加到主屏"引导（iOS 无此事件，展示手动引导图）。
- Web Push：VAPID；SW `push` 事件展示通知，`notificationclick` 深链到 `/today?focus=tickbar`。

## 6. 后端技术设计（apps/server）

### 6.1 模块划分（Hono）

```
src/
├── routes/        auth / capsules / tags / seals / reports / reminders / export / events
├── services/      capsule.service / seal.service / report.service / quota.service
├── ai/            provider适配器(deepseek|qwen|doubao) / prompt-builder / privacy-filter
├── jobs/          reminder.job（每分钟） / export.job / cleanup.job（注销冷静期清理）
├── core -> @tickcap/core   （归属日、推断、streak 等与前端共享）
└── middleware/    auth / rate-limit / request-id / error-handler
```

### 6.2 提醒调度（无 Redis 版）

`node-cron` 每分钟执行：查询"到点该提醒"的用户（SQL 直接算：当前时区时刻在 active 窗口内、距上次记录 ≥ interval_min × 0.6、距上次提醒 ≥ interval_min、未暂停、weekday 匹配）→ 逐个 Web Push → 写 `events(reminder_sent)`。未响应降频（`snooze_level`）在夜间任务统一评估。单实例即可支撑 10 万级用户，这条查询要有覆盖索引。

### 6.3 AI 生成流水线

封存 → `ai_reports` 插入 `pending` 行 → 进程内队列（并发 2，p-queue）→ privacy-filter 剔除敏感胶囊内容 → prompt-builder 组装 → 供应商流式调用 → 边生成边写缓冲 + 推给 SSE 订阅者 → `done`。失败重试 2 次后置 `failed`，前端提供"重试"按钮。详见 [08](08-AI复盘技术设计.md)。

### 6.4 安全清单

- 全局限流（IP + 用户双维度）；验证码接口独立更严限流
- JWT：access 2h / refresh 30d 旋转；refresh 哈希落库可吊销
- 输入校验统一 zod schema（与前端共享自 `@tickcap/api`）
- SQL 全走 Drizzle 参数化；detail 字段渲染前 sanitize（防存储型 XSS）
- 导出/注销等敏感操作二次确认 + 操作日志

## 7. 测试策略与 MVP 验收标准

### 7.1 测试分层

| 层 | 工具 | 范围 |
|----|------|------|
| 单元（必须） | Vitest | `@tickcap/core` 全覆盖：归属日（日界边界、跨零点）、时间推断（首颗/续记/夹缝）、streak（宽限、解封重封）、空隙计算 |
| API 集成 | Vitest + docker Postgres | 认证流、胶囊 CRUD 幂等、封存幂等、配额 |
| E2E | Playwright（移动视口） | 冒烟主链路：登录 → 滴答 3 颗 → 调时间 → 封存 → 看复盘 → 档案馆回看 |
| Prompt 回归 | 自建脚本 | 见 [08 §6](08-AI复盘技术设计.md) |

### 7.2 MVP 功能验收标准（抽核心）

| 功能 | 验收标准 |
|------|----------|
| 滴答记录 | 冷启动 → 完成一颗胶囊 ≤3 次交互；断网滴答，恢复后自动同步且不重复 |
| 时间推断 | 连续记录时用户 0 次触碰时间选择器即得到无缝流水账；凌晨 01:00 记录出现在昨日轴 |
| 时间轴 | 8 颗胶囊的一天，滚动 60fps（中端安卓 Chrome 实测）；重叠胶囊并列展示不遮挡 |
| 封存 | 封存后 5s 内复盘开始流式输出；重复点击封存不产生重复报告；次日 11:59 补封昨日 streak 连续 |
| 提醒 | 间隔内已记录则该次提醒被跳过；连续 3 次未响应后自动降频且 App 内可见说明 |
| 数据导出 | 导出包内 Markdown 按天成文、JSON 结构完整可重新导入 |
| 账号 | 注销后 7 天内可撤回，逾期数据物理清除 |

## 8. 环境与发布

- 环境：local（docker-compose: pg + server + web）→ staging（单机 Docker，独立库）→ prod
- CI（GitHub Actions）：lint + typecheck + 单测 + 集成测试 → 构建镜像 → staging 自动部署，prod 手动确认
- 数据库迁移：drizzle-kit 生成 SQL 迁移文件入库，禁止手改线上 schema
- 监控：服务端结构化日志 + 错误上报（Sentry 自托管或轻量替代）；`ai_reports` 成本日报（token 用量 × 单价）自动入群/邮件
