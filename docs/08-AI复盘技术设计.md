# 08 · AI 复盘技术设计

> AI 复盘是本产品的"收获时刻"与付费理由，质量即命脉。本文定义数据打包、Prompt 架构、模型路由、生成流水线、质量评估与成本控制。

## 1. 设计原则

1. **结构化输入是护城河**：AI 拿到的不是一段日记，而是带时间戳、时长、标签、心情的结构化流水——这是复盘质量超过一切"AI 日记"竞品的根本。
2. **AI 是教练不是作者**：输出永远可编辑；用户手写的"补一笔"和编辑版永不被覆盖；不做道德评判。
3. **隐私硬边界**：敏感胶囊内容在打包层物理剔除，不依赖 prompt 承诺。
4. **成本可控**：按报告类型路由模型档位；缓存与幂等防重复烧钱。

## 2. 数据打包（Context Builder）

日复盘的输入 JSON（由 `@tickcap/core` 的 `buildDailyContext()` 生成，前后端同构可测试）：

```json
{
  "date": "2026-07-27", "weekday": "周一",
  "day_summary": { "capsule_count": 11, "recorded_minutes": 620,
                   "first_at": "07:00", "last_at": "22:30",
                   "by_tag": [{"tag": "工作", "minutes": 300, "pct": 48}, ...],
                   "gaps_minutes": 95, "mood_curve": [{"t": "07:20", "mood": 4}, ...] },
  "capsules": [
    { "t": "07:00-07:20", "tags": ["起床"], "summary": null, "mood": null },
    { "t": "07:20-08:20", "tags": ["通勤"], "summary": "地铁上看完那篇讲定价的文章",
      "detail": "……(原文)", "mood": 4 },
    { "t": "09:00-11:00", "tags": ["工作"], "summary": "写 Q3 方案",
      "highlight": true, "detail": "终于把定价那节写顺了……" }
  ],
  "streak": 12,
  "recent_context": "（P1）近 7 日一句话摘要，用于'对比昨天/本周趋势'"
}
```

**隐私过滤规则（privacy-filter，在打包最后一步执行）**：
- `is_private = true` 的胶囊：保留 `{t, tags, minutes}`（时长统计仍准确），剔除 `summary/detail/mood`，注入占位 `"private": true`——AI 知道这段时间存在但不知内容，复盘对其保持沉默。
- 用户在设置中可选"完全本地统计模式"（P2）：AI 功能整体关闭。

## 3. Prompt 架构（三层组装）

```
[系统层 system]      产品身份 + 硬规则（不评判、不编造、引用用户原话须准确、
                     中文口语化、禁止空话套话、长度约束）
[人设层 persona]     温柔陪伴 / 客观分析 / 严厉教练 —— 只改语气与视角，不改结构
[模板层 template]    输出结构定义（默认复盘 / KPT / 极简三行 / 感恩 / 效率教练）
                     + 少样本示例（每模板 1 个高质量示例，锚定文风）
[数据层 context]     §2 的 JSON
```

- 三层独立版本化：`prompts/system-v3.md`、`prompts/personas/*.md`、`prompts/templates/daily/*.md`，报告行记录 `prompt_version = "sys3+warm2+kpt1"`，可精确回滚与 A/B。
- 模板 spec 存 `templates.spec`（jsonb）：`{sections: [...], tone_hints, length, few_shot}`。用户自定义模板（会员）= 用自然语言描述需求 → 一次性让大模型编译成 spec → 人工可再调。
- 关键细节要求写死在系统层：
  - **高光时刻必须引用用户原文**（带引号），禁止改写替用户"升华"
  - **"明日一问"**必须基于当天具体内容，禁止通用问题（"今天最大的收获是什么"这类一律不合格）
  - 时间账单的点评一句话以内，数据由前端图表呈现，AI 不复述数字清单

## 4. 模型路由与成本

| 报告类型 | 模型档位 | 预估输入/输出 | 单次成本（估） |
|----------|---------|--------------|---------------|
| 日复盘 | 中档（DeepSeek-chat / qwen-plus 级） | ~2.5k / ~0.7k tokens | ≈ ¥0.005–0.01 |
| 周报 | 高档（deepseek-reasoner / qwen-max 级） | ~6k / ~1.5k | ≈ ¥0.05–0.1 |
| 月报/年报 | 高档 + 两段式（先分周摘要再汇总） | ~15k / ~3k | ≈ ¥0.2–0.5 |
| 模板编译（自定义模板） | 高档，一次性 | 小 | 忽略 |

- 成本口径：重度免费用户（每周 3 次日复盘）月成本 < ¥0.15；Pro 用户全开月成本 < ¥1.5，对 ¥8.2/月定价成本占比 <20%，符合 [03](03-商业化设计.md) 的 25% 红线。
- 供应商适配器接口：`generate(messages, {model_tier, stream}) → AsyncIterable<delta>`；DeepSeek / 通义 / 豆包三家实现，配置化主备切换（主供应商 5xx 超阈值自动切备）。
- 幂等与防刷：同一 `(user, date, template, persona, prompt_version)` 且输入数据未变 → 直接返回既有报告（输入哈希比对）；重新生成限 5 次/天/用户。

## 5. 生成流水线与失败兜底

```
封存 → ai_reports(pending) → 进程内队列(并发2)
  → privacy-filter → prompt-builder → LLM 流式
  → 增量写缓冲 & 推送 SSE(delta) → 完成写 content_md, status=done
失败 → 退避重试 2 次 → status=failed → SSE(failed)
```

前端兜底策略（体验不能因 AI 挂掉而挂掉）：
- `failed`：复盘区展示**本地降级版复盘**（前端用 `day_summary` 纯规则渲染：时间账单图 + 高光星标列表 + 手写框）+ "AI 复盘生成失败，点击重试"。封存本身照常完成，streak 不受影响。
- 排队超 30s：先展示本地降级版，AI 完成后平滑替换。
- **封存动作与 AI 生成解耦**是铁律：AI 是复盘的增强，不是封存的依赖。

## 6. 质量评估（Prompt 不靠感觉调）

1. **金标数据集**：内测期积累 30 份真实"一天数据"（脱敏授权），覆盖典型形态：充实工作日 / 摸鱼日 / 周末生活日 / 只有 3 颗胶囊的低记录日 / 含情绪波动日。
2. **回归脚本**：每次改 prompt，对金标集全量生成，双维评估：
   - 规则检查（自动）：长度合规、结构完整、引用原文准确（字符串匹配）、"明日一问"非通用句（黑名单匹配）
   - LLM-as-judge（自动初评）+ 人工抽检：具体性、洞察力、口吻符合人设，1–5 分
3. **线上指标**（见 [09](09-埋点与数据指标.md)）：复盘完整阅读率、"补一笔"填写率、编辑率、重新生成率（过高 = 质量差信号）。
4. 低记录日（<4 颗胶囊）走专用短模板——数据少还硬写长复盘必然空话连篇，宁短勿水。

## 7. 合规

- 仅调用已完成生成式 AI 备案的国内大模型 API（DeepSeek/通义/豆包官方）
- 用户内容用于生成其本人报告，不用于模型训练；与供应商协议勾选"不留存/不训练"选项
- 隐私政策明示：哪些数据会发送给大模型、敏感胶囊如何被排除
- AI 生成内容标注"由 AI 生成，可编辑"（合规要求 + 产品理念一致）
